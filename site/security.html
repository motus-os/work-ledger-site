Security

Motus blocks ordinary changes to a local ledger and checks it for inconsistencies. Anyone who controls the database file can still rewrite it.

What Motus checks

  • state paths and private POSIX permissions
  • schema version and required SQLite objects
  • database integrity and foreign keys
  • event and finding payload hashes
  • event sequence order and finding run links
  • terminal events against their run projections

SQLite rules block normal updates, deletes, missing event numbers, events after a run closes, run deletion, and changes to closed runs. Closing a finding adds a separate record; the original does not change.

Trust boundary

Anyone who controls the database can remove these protections and rewrite the records and hashes. motus doctor checks the current file but cannot prove this never happened.

Receipts are unsigned local records. Motus does not observe the command independently or prove that the work was correct.

Sensitive data

Motus creates run records without command argument values, stdin, raw output, environment variables, source files, prompts, or transcripts.

Motus stores the finding summary, likely cause, next step, or closure note that you submit. Review that text before recording it.

Report a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's private vulnerability-reporting form.

The complete, versioned policy lives in SECURITY.md.
