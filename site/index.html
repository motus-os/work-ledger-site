See a finding in use.

A test fails because a generated file is stale. The developer records the explanation and next step with the failed run. Later, a coding agent searches before testing and gets the finding with its source run.

Example output is abridged. IDs are shortened.

Earlier

$ motus wrap -- npm test
motus: recorded run_0370... (failure)

$ motus finding add --run run_0370... --file finding.txt
Recorded finding_1457... (open)
Finding

The generated file was stale. Generate before testing.

Later

$ motus finding list --query generated
finding_1457...  open  The generated file was stale.

$ motus finding show finding_1457...
Origin run: run_0370...  failure
Summary: The generated file was stale.
Next step

Generate the file, then run the test through Motus. If it passes, close the finding with that successful run. The original finding stays unchanged.

Use the same workflow for a constraint, workaround, or decision tied to a specific run.

Install Motus and record a run.

Download a release for macOS, Linux, or Windows, or install with Go. Put Motus in front of a test, build, script, or check you already run.

Motus creates .motus/ledger.db at the project's Git root by default. Add .motus/ to .gitignore. Use the same state directory wherever people, coding agents, scripts, or CI need the same records.

Read the complete workflow

$ go install github.com/motus-os/work-ledger/cmd/motus@latest
$ motus version
$ motus wrap -- npm test
$ motus finding add --run run_... --file finding.txt
$ motus finding list --query generated
$ motus finding show finding_...

Motus runs on demand, uses SQLite, and requires no account or hosted service. It does not upload the ledger or store raw command output.

Motus Work Ledger is open source under Apache-2.0.
