Keep the fix with the failure.

When a command exposes a problem, the reason and the fix often end up split across terminal output, chat, commits, and memory. Motus connects the failed run, the explanation you want to keep, and the successful run that resolved it, so the next attempt can start with what worked.

The run keeps the facts. The finding keeps the reason.

Motus sits around a command you already use. It records selected machine facts, then lets you add the explanation you choose to keep.

  1. 01 Record

    Run a test, build, script, or tool through Motus.

    motus wrap -- ...
  2. 02 Explain

    If the run exposes a failure you may see again, keep the cause or next step.

    motus finding add
  3. 03 Resolve

    Connect the finding to the successful run that fixed it.

    motus finding close
  4. 04 Find later

    Search your words and inspect both runs when the problem returns.

    motus finding list --query

The record is there when the problem returns.

The run supplies the facts

Motus records the executable name, Git state, timing, exit status, outcome, and output counts.

You supply the meaning

The finding stores the summary, hypothesis, or next step you deliberately submit through a file or standard input.

The fix stays traceable

Resolving a finding connects it to a closed successful run without changing either run receipt.

1

Install

go install github.com/motus-os/work-ledger/cmd/motus@latest

Requires Go 1.26.5 or newer. You can also use a verified archive from GitHub Releases.

2

Record and explain

Run the command Motus prints after the failure. Enter one line, then press Ctrl-D on macOS or Linux. On Windows, press Ctrl-Z and then Enter.

motus wrap -- YOUR_COMMAND
motus finding add --run FAILED_RUN_ID --file -
3

Resolve and find later

Run the fix through Motus. Use the successful run ID, enter a closure note, then finish input the same way.

motus wrap -- YOUR_COMMAND
motus finding close FINDING_ID --disposition resolved --run SUCCESS_RUN_ID --file -
motus finding list --query stale

What stays in the local ledger.

The ledger keeps machine facts about selected runs and the findings you choose to add.

Recorded with a run

  • stable run and event IDs
  • timestamps and duration
  • executable name and argument count
  • Git repository, commit, and dirty state
  • exit code, signal, timeout, and outcome
  • output byte and line counts

Written by you

  • finding summary and analysis
  • next step, when useful
  • resolution or dismissal note
  • origin and resolving run links

Questions.

Why not Git, shell history, or CI logs?
Those tools preserve source changes, commands, or execution output. Motus connects a selected run, the explanation you kept, and the run that resolved it in one local record.
Does Motus store raw command output?
No. It streams output normally and records counts. Finding text is stored only when you add it deliberately.
What does a receipt establish?
It is a deterministic projection of a closed run in your local ledger. The included SHA-256 digest checks the receipt body against its envelope. Read the security model.
