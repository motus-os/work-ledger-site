Save the explanation with the run.

Motus is a local work ledger. It links selected facts about a command run to a note written by a person or agent, so a later caller can find both.

Install Motus View the example

  3. An agent searches later generated file
  4. The agent acts Generate first, then run the test.

See a finding in use.

A test fails because a generated file is stale, so the developer records what happened and what to run next. Later, a coding agent finds the note before running the test again.

Example output is abridged. IDs are shortened.

Earlier

$ motus wrap -- npm test
motus: recorded run_0370... (failure)

$ motus finding add --run run_0370... --file finding.txt
Recorded finding_1457... (open)
Written by the developer

The generated file was stale. Run generation before testing.

Later

$ motus finding list --query generated
finding_1457...  open  The generated file was stale.

$ motus finding show finding_1457...
Origin run: run_0370...  failure
Summary: The generated file was stale.
What the agent does next

Run generation, then record the test through Motus. The caller can link the successful run when closing the finding.

Standing instructions belong in a README. Motus stores run-specific explanations, constraints, workarounds, and next steps as searchable findings.

Use it with commands you already run.

Wrap a test, build, script, or check. Add a finding only when the work produced something worth keeping.

Motus stores this project's ledger at .motus/ledger.db. Add .motus/ to .gitignore. People, agents, scripts, and CI use the same commands and state directory when they need the same records.

Read the complete workflow

$ go install github.com/motus-os/work-ledger/cmd/motus@latest
$ motus version
$ motus wrap -- npm test
$ motus finding add --run run_... --file finding.txt
$ motus finding list --query generated
$ motus finding show finding_...

Records stay in a local SQLite ledger and require no account or service. Motus does not store raw command output.
